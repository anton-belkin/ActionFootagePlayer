打开片段

无需导入，没有媒体库，也不必先渲染：片段在哪里，就在哪里播放。

双击片段

Mac App 的设置会把它设为 MP4 视频的默认 App（macOS 会请你确认）：双击 MP4 即可播放，本页的所有功能都会生效。其他视频可以通过访达的“打开方式”用它打开。

访达的快速操作

macOS

右键 → 快速操作：Play Stabilized 在播放器中打开所选视频；Stabilize + LUT 在后台导出它们，每完成一个都会发出通知。

文件资源管理器的菜单

Windows

MP4 和 MOV 视频的“打开方式”中有 ActionFootagePlayer，文件资源管理器的菜单中有 Play in ActionFootagePlayer 和 Stabilize + LUT，后者在单独的窗口中导出并显示进度（Windows 11 上在“显示更多选项”里）。

一个窗口，整个文件夹

面板 → Source、Output

播放时再打开一个视频，它会取代当前视频。文件夹中的其他视频就是上一个和下一个片段：侧边面板 Source 和 Output 底部的 In the folder（在文件夹中）有 Previous clip（上一个片段）和 Next clip（下一个片段）。Autoplay next（自动播放下一个）开启时（默认），一个片段播完，就播放文件夹中的下一个；关闭时，每个片段在结尾暂停。Loop the clip（循环播放片段）会一遍又一遍地播放它。

片段的信息

面板 → Source

侧边面板 Source 的顶部显示：相机型号、它是怎么录制的（Log 及其曲线、HDR 或 SDR，以及 HDR 文件的 Dolby Vision profile）、它的镜头、是否有运动数据和遥测数据，以及有几个标记。

如何读取，设定一次

面板 → Source

有三项说明文件本身该如何读取：它的 Log curve（Log 曲线）、是否 Recorded turned（录制时有旋转），以及镜头是否 Under water, flat port（水下，平面镜罩）。它们根据文件和相机得出；改动其中一项，改动仅用于观看，直到 Save to the source（保存到源）把它保存下来，用于这个片段以及它所有的精彩瞬间和片段预览。Revert to saved（恢复为已保存）恢复原样。每个片段保留自己的设置：这些都不会带到下一个片段。

原始文件保持原样

你的原始文件保持原样，除非你剪掉其中拍坏的一段：这时片段会被重写，去掉这一段，不重新编码，原始文件则移到废纸篓。片段旁边只放你自己的小文件：它的 Gyroflow 项目，即一个 .gyroflow 文件，以及 <clip>.afp.json，里面是你的标记和你为片段保存的播放方式。精彩瞬间和导出的文件放在项目文件夹里。

直接来自相机

播放从存储卡上原样拷贝的片段。经过其他 App 导出或裁剪的片段会丢失播放器读取的元数据：Log 模式、运动数据、遥测数据和精彩时刻。

Log 色彩与风格

Log 是相机记录信息最多的模式，但片段看起来又平又灰，通常需要调色。在这里，它们直接以完整色彩播放。

Log 素材，一步步讲清楚 →

自动识别 Log

判断是否为 Log 依据的是片段的元数据，而不是文件名，所以无需任何设置：Osmo Action 6 和 Osmo 360 的 D-Log M，近期 GoPro 的 GP-Log 和 GP-Log2。普通片段照常播放。

已验证 Osmo Action 6（D-Log M）；GoPro HERO12 Black（GP-Log，固件 1.20 或更高） 应可用 Osmo 360；HERO13 Black；GP-Log2（MISSION 1）

以 HDR 播放 Log

Ctrl+h

D-Log M、D-Log、GP-Log、GP-Log2 和 10-bit I-Log 会被转换为 HDR（Rec.2100 HLG）：这是固定的技术性转换，所有片段都一样，不添加任何创意风格。Ctrl+h 直接切换到 HDR。

手动选择 Log 曲线

Ctrl+l · 面板 → Source

适用于元数据中没有注明的片段：D-Log M、D-Log、GP-Log、GP-Log2 和 I-Log（10-bit），在侧边面板的 Source → Log curve 中选择，或用 Ctrl+l 依次切换。这是片段的读取方式：Save to the source 会把它保存下来，用于这个片段以及它所有的精彩瞬间和片段预览。标记为 HDR 的文件不会被当作 Log；如果它其实是 Log，可以用 Grade as log by hand…（手动按 Log 调色）。

应可用 Insta360 单镜头，10-bit I-Log 尚不支持 8-bit I-Log

SDR 风格

Ctrl+s

SDR：经 NBCUniversal 中性的 HLG → SDR 转换（所有相机都一样），经相机厂商自己的 Rec.709 LUT（D-Log M 用 DJI 的），或由 mpv 色调映射。Ctrl+s 会在它们和 HDR 输出之间依次切换。

尚不支持 D-Log M 以外曲线的厂商 Rec.709 LUT

DJI 的 LUT，从 DJI 获取

DJI 的 Rec.709 LUT 不随本项目分发：App 的设置会从 DJI 下载并校验它。HDR 和 NBCU 的 SDR 不需要它。

按录制原样

L

对当前片段关闭 Log 处理：文件原样显示，就像相机录下的那样平淡。

HDR 文件原样播放

标记为 HDR 的文件，无论是 HLG 还是 PQ（导出的文件，手机或运动相机拍的 HDR 视频），以 HDR 播放，不套用 LUT，也绝不会被当作 Log 再调一次色。Ctrl+s 以 SDR 显示它，经 NBCU 的转换或由 mpv 色调映射。在 Mac App 中，它还有 Dolby Vision 风格，带播放器的 trim 参数：HLG 文件为 HLG+DV，PQ 文件为 PQ+DV。自带 Dolby Vision 的文件（profile 8）也能用它自带的 Dolby Vision 播放：HDR, its own Dolby Vision 和 SDR, its own Dolby Vision。Profile 5 没有可以依托的 HDR 基础层，所以由 mpv 做色调映射。

应可用 PQ+DV 风格

按片段类型提供的风格

面板 → Output → Display

侧边面板的 Output → Display 只列出这个片段具备的风格，上方有一行说明它是什么，例如 From Log, D-Log M：

  • Log：HDR，两种 HLG+DV 风格（Mac App），三种 SDR 风格，以及 As recorded, log；
  • HDR，HLG 或 PQ：按录制原样，Dolby Vision 风格（Mac App），由 mpv 色调映射的 SDR，以及经 NBCU 转换的 SDR；
  • SDR：只有一种风格，SDR, as recorded。如果它其实是 Log，就在 Source 中选择它的曲线。

风格属于屏幕，不属于片段：它不会和片段一起保存。

任何屏幕上的 HDR

在 HDR 屏幕上，Log 只需要技术性转换，每个片段都一样，所以可以自动完成。在没有 HDR 屏幕的 Mac 上，由 macOS 针对该屏幕对 HDR 做色调映射，并用上每一帧自己的亮度信息。

HDR、SDR 和 Dolby Vision，一步步讲清楚 →

片段的起始输出

在 HDR 屏幕上（例如 MacBook Pro 的屏幕），Log 片段以 HDR 开始播放。在没有 HDR 屏幕的 Mac 上（MacBook Air，大多数外接显示器），Mac App 让片段以 HDR, HLG+DV 开始播放：HLG 通过 macOS 自带的 Dolby Vision® 显示管理呈现，由它针对该屏幕做色调映射，与 QuickTime 和 Apple 设备显示导出文件的方式相同。你用 Ctrl+s 选择的输出，就是本次会话中后续片段在同类屏幕上的起始输出。

视频输出

Ctrl+s

切换到片段的下一种视频输出（只在片段具备的输出之间切换）：

  • HDR, HLG：HDR；在没有 HDR 的屏幕上，由 macOS 做色调映射；
  • HDR, HLG+DV：在 HDR 屏幕上是 HDR，在没有 HDR 的屏幕上由 trim 参数做色调映射；
  • SDR, HLG+DV：在 HDR 屏幕上也由 trim 参数做色调映射，也就是 SDR 屏幕上看到的样子；
  • SDR：由 mpv 色调映射，经 NBCUniversal 中性的 HLG → SDR 转换，或经相机厂商自己的 Rec.709 LUT（D-Log M 用 DJI 的）。

在 HDR 屏幕上，这些 SDR 输出会以 SDR 屏幕上的样子显示。已经是 PQ HDR 的文件也有同样的两种 Dolby Vision 输出，即 HDR, PQ+DV 和 SDR, PQ+DV。

Mac App HLG+DV 和 PQ+DV 输出

每一帧自己的亮度

Mac App

使用 HLG+DV 时，每一帧的最暗、平均和最亮亮度会随帧一起送出（Dolby Vision 的 L1），在播放时由 GPU 测得，因此 macOS 会按每个场景的实际内容做映射，而不是按一个典型场景：昏暗的潜水画面和阳光下的海滩各有各的空间。以 HLG+DV 风格导出的文件，也以同样的方式测量每一帧。

trim 参数：作者的，或中性的

Mac App

trim 参数叠加在每帧的亮度之上：作者按个人喜好设定，贴合 NBCUniversal 的 HLG → SDR 转换，且没有场景级偏移，所以 HDR 屏幕上看到的仍是 HDR。侧边面板的 Dolby Vision 中有对应的滑块，并可以恢复为作者的设定或中性设定（Dolby Vision 自身的映射，不加任何调整）。以 HLG+DV 风格导出的文件采用那里的设置。

面向 Apple 设备的导出文件

Mac App

以 HLG+DV 风格导出时（也就是 Mac App 在没有 HDR 的屏幕上的起始风格），片段会成为 HEVC Main10 HLG，并带有 Dolby Vision Profile 8.4 元数据：播放器自行写入兼容的元数据（RPU）。Apple 设备（iPhone 或 Mac）以 HDR 播放它，在标准屏幕上则应用 trim 参数，因此显示效果与播放器中一致。不支持 Dolby Vision 的设备会把它当作普通的 HLG 播放，并自行做色调映射。

以 PQ+DV 风格导出的 PQ 文件，同样会得到 Dolby Vision Profile 8.1，基于它的 HDR10（PQ）基础层。文件自带的 Dolby Vision 不会带进导出的文件：不用这些风格，它就导出为普通的 HDR。

以 HDR, HLG 导出的文件，以及 Stabilize + LUT 和命令行导出的文件，都是普通的 HLG。在 Windows 或 Linux 上导出的文件从不带 Dolby Vision。

另一类屏幕

片段的窗口移到另一类屏幕时，片段保持原来的风格。在 Windows 和 Linux 上，所有屏幕都视为 HDR。

显示器显得太暗

macOS

连接过 HDR 显示设备（例如 HDR 电视）之后，在 Mac 重启之前，macOS 可能会把接在它原来位置上的 SDR 显示器上的 HDR 显示得暗大约一档。播放器发现这种情况时会提示你，就在 HDR 第一次在这种显示器上播放的时候。

防抖

使用 Gyroflow 的引擎，在片段播放的同时进行，与 Log 转换同步：无需先渲染。

防抖，一步步讲清楚 →

基于相机自己的运动数据

Ctrl+g

关闭相机防抖录制的片段，无需项目即可防抖播放：DJI 需关闭 EIS 并使用 Wide 视角（只有这样它才会记录自身的运动），GoPro 关闭 HyperSmooth，Insta360 关闭 FlowState。前提是相机记录了防抖已关闭：相机已经防抖过的片段按原样播放。

已验证 Osmo Action 6（关闭 EIS）；GoPro HERO12 Black（关闭 HyperSmooth） 应可用 Osmo 360；其他 DJI 相机；其他 GoPro；Insta360 单镜头 尚不支持 其他相机，在没有项目的情况下

无需预先渲染

以前旅行的素材直接以防抖效果播放，不需要为每个片段渲染并保存一份副本：只有你导出的段落才会写出文件。

防抖本身来自 Gyroflow 的引擎；播放器在此之上加入实时播放、Log 转 HDR 和遥测数据。

开启、更宽、关闭

Ctrl+g · 面板 → Transform

Transform → Stabilization：On（开启）放大到不露出边缘；Wider（更宽）不放大，防抖后的画面在窗口中覆盖的面积与原画面大致相同，边缘有时会露出，并被填充；Off（关闭）不防抖，除非 Lens 为 As recorded，镜头仍会校正。Ctrl+g 按 On → Wider → Off 切换。有项目的片段以 On 开始，与 Gyroflow 中的设定一致。

防抖强度

Ctrl+k

Transform → Level，适用于没有项目的片段：Weak（弱）、Medium（中，默认）或 Strong（强），裁切 10、20 或 30 %，平滑度 50、75 或 100 %。播放中即可切换。

地平线

面板 → Transform

Level（保持水平）或 Free（不锁定），适用于没有项目的片段。默认值来自预设：播放器自带的预设为 Free。Level 需要更多放大，所以边缘露出得更多。

随片段保存

面板 → Transform

片段如何显示，就是它的变换：防抖、强度、地平线、镜头和投影、画幅，以及水下色边校正。它作为一个整体保存，从不单独保存其中一项设置。Transform 顶部的卡片说明正在播放的变换来自哪里：本次会话（没有为它保存任何设置）、源、精彩瞬间或片段预览。

  • Save（保存；Save to the source、to the moment、to the clip preview）把正在播放的设置写到那里；对片段来说，写入它旁边的 <clip>.afp.json。每项设置都会在角上用圆点标出已保存的选择。
  • Revert to saved（恢复为已保存）回到已保存的设置。
  • Auto save（自动保存，默认关闭，仅限本次会话）边用边保存：没有保存任何设置的片段，打开时就保存正在播放的设置，之后每次改动都保存。
  • Use as default（设为默认）让它成为没有保存任何设置的片段的起始设置。

已保存变换的片段按保存的样子打开，不管默认设置是什么，你在它上面的改动仅用于观看，直到你保存。在没有保存任何设置的片段上，你的改动也会沿用到后面的片段。

镜头，单独设置

面板 → Transform → Lens

Corrected（校正，默认）或 As recorded（录制原样），与防抖分开：防抖为 Off、镜头为 Corrected 时，只校正镜头，什么都不平滑。有镜头配置文件但没有运动数据的片段就这样播放。这需要镜头是已知的（Source 会显示它的配置文件）；手动选择配置文件以后才会提供。

鱼眼效果

面板 → Transform → Lens

镜头校正后，如何把画面展平：Linear，直线保持笔直（默认），或 Fisheye 1 到 Fisheye 4（球极投影、等距投影、等立体角投影、正交投影）。

整个片段的画幅

面板 → Transform → Frame

片段的形状：Own（视频自己的）、16:9、4:3、5:4 或 1:1，以及 As is（原样）、Landscape（横向）或 Portrait（竖向），竖向时它们变成 9:16、3:4 或 4:5。片段按它播放，导出、精彩瞬间、片段预览和照片也都按它制作。Make a Gyroflow project…（Ctrl+e）把它写进一个新项目，在那里还可以设置缩放。

转着拍的片段，以正向显示

面板 → Source

相机转着拍的片段（倒置，或竖着拿）会按文件所写，以正向播放、防抖和导出。文件没有注明时，由 Source → Recorded turned 设定：As is、90° ↻、180° 或 90° ↺，用 Save to the source 保存。旋转在防抖之前进行。

已验证 转着拍的片段以正向播放

Gyroflow 项目

在 Gyroflow 中制作并保存在片段旁边的项目会被原样使用：片段按项目设定播放。它设定的内容只属于项目：平滑、地平线、画幅、投影，以及片段录制时的旋转和镜头是否在水下。Transform 把它们列在 In the Gyroflow project（在 Gyroflow 项目中）下，并附有 Edit in Gyroflow…；播放器从不写入它们。在项目之上，你可以用 Wider 或 Off 查看它，或者让镜头 As recorded，仅用于观看。对应项目所设定内容的快捷键会说明这一点，并提示用 Ctrl+e 在 Gyroflow 中编辑。

已验证 Osmo Action 6 应可用 其他相机，以及 Gyroflow 支持的任何相机

在 Gyroflow 中打开

Ctrl+e

暂停播放，并在 Gyroflow 中打开片段的项目；如果还没有项目，会先根据你看到的效果在片段旁边写入一个：同样的镜头、平滑、放大、画幅和折射。每次在 Gyroflow 中保存，这里的防抖都会在同一位置重新加载。已存在的项目绝不会被覆盖。

Windows 没有项目的片段需要在 gyroflow.conf 中设置 gyroflow_appLinux PATH 中要有 gyroflow，或者设置 gyroflow_app

没有运动数据？用 Gyroflow

Ctrl+e

播放器自己无法防抖的片段，会原样在 Gyroflow 中打开。没有运动数据的片段（开着 EIS 的 DJI，或根本不记录运动数据的相机）在那里从画面本身进行防抖（光流）；开着相机防抖拍摄的 GoPro 或 Insta360 片段带有运动数据，Gyroflow 会加载它。在那里保存项目后，片段就会用它防抖播放。侧边面板中对应的是 Stabilize in Gyroflow…

许多没有运动数据的片段：Stabilize optically

Action Footage Library

在 Action Footage Library 中选中片段或文件夹，按 Stabilize optically（光学防抖）：Gyroflow 从每个片段的画面中测出它的运动，在后台一个接一个地进行，所需时间大约与片段的播放时长相当，它的项目放在片段旁边。不需要的片段会被排除，并逐个说明原因。它需要能从命令行做光学分析的 Gyroflow，在这项功能进入 Gyroflow 官方版本之前，需要用我们的分支构建。

近距离的横向抖动

Ctrl+j · 面板 → Transform

陀螺仪防抖去掉的是相机的转动；近距离拍摄时，手的细小横向位移仍然会让画面晃动。Measure for this clip（为此片段测量）根据相机的加速度计和画面，把这些位移测量一次并保存下来；之后播放时，画面会朝相反方向移动来抵消它们。Ctrl+j 先测量，之后用来关闭和开启。

已验证 Osmo Action 6

从 NAS 播放也很快

防抖先读取它最先播放的那一段的运动数据，其余的边播边读。NAS 上一个 2.5 GB 片段中的精彩瞬间，3 到 5 秒就能显示，而第一次打开需要 22 秒；整个片段需要 1.5 到 3 秒。

水下

相机内置防抖是为陆地调校的。水会折射光线，镜头的表现就像一支比它所调校的焦距更长的镜头。关掉它，片段在这里就能稳定播放：默认预设专为水下素材制作，并校正了水对光线的折射。在一段测试片段上，帧间抖动从 0.16 px 降到了 0.02 px。

镜头在水中或水外

Ctrl+u · 面板 → Source

Source → Under water, flat port（水下，平面镜罩）：Auto（默认）、Yes 或 No（在水上，或位于球面镜罩之后）。Auto 在整段片段中跟随相机记录的 In water / Out of water，在一帧之内切换；不记录这一信息的相机，采用预设的设定（默认为水下）。这是片段的读取方式，所以 Save to the source 会为这个片段保存它。Gyroflow 项目会自己设定它，而且它需要已知的镜头。Ctrl+u 在水下和水上之间来回切换。

跟随相机：仅 Osmo Action 6，它是唯一记录这一信息的相机。

边缘填充

Ctrl+b · 面板 → Performance & Quality

防抖后画面未覆盖的区域用什么填充，经过模糊并融合进画面：

  • Trail by direction（按方向留下的轨迹），默认：在真实世界中这个方向上最后一次看到的内容，所以平移镜头时也能与画面吻合；尚未看到过的地方，用周围的颜色向内扩散；
  • Frame's edge spread out（画面边缘向外扩散）：只用画面自身的颜色，从边缘向外扩散；
  • Background color（背景色）：项目的背景色，与 Gyroflow 渲染的一样。

立即开始播放

没有项目的片段读完开头几秒的运动数据就开始播放，其余部分边播边读：从 NAS 播放约一秒即可开始，而先读完全部数据需要 5-10 秒。

在较慢的电脑上

面板 → Performance & Quality

正前方跟随什么

Camera（相机）：相机指向的方向，在几秒内平滑（没有 GPS 时的默认）。World（世界）：开始时看向的方向，保持不变。Way（行进方向）：沿着你移动的方向，来自 GPS 轨迹。North（北）：正北，来自 GPS 轨迹。Way 和 North 需要录制时带 GPS 的片段；片段无法提供的模式呈灰色，并说明原因。

项目、精彩瞬间与标记，一步步讲清楚 →

保存精彩瞬间

k

按两次 l 标记一段，再按 k，播放器先询问名称，再把这一段保存为精彩瞬间。输入框是空的，旁边显示一个建议名称：Enter 采用它，直接输入则替换它，Esc 取消。没有起名的精彩瞬间以它的日期和时间命名。

一个精彩瞬间就是一个小文件

每个精彩瞬间都是项目 _Moments/Generated/ 文件夹里的一个小 MP4，以它的名称命名：<name>.afplink.mp4。访达的缩略图和快速查看文件资源管理器的缩略图和预览窗格（Alt+P）都以正常色彩显示它，而不是 Log 的灰色。在播放器中打开，它会以完整画质播放原始文件中的这一段，显示效果与你保存时一样：它完整的变换，包括防抖和画幅。

它的图标是其中的第一个标记，没有标记时则是中间那一帧。文件日期就是这一刻真实发生的时间，所以按日期排序时，精彩瞬间会按发生的先后排列。

像普通文件一样整理

删掉文件，就删掉了这个精彩瞬间。把它移进项目文件夹中任何你自己的文件夹、重命名它：它仍然是一个精彩瞬间，靠里面的链接被找到。

Settings of its own（自己的设置）

面板 → Transform

精彩瞬间按正在播放的设置制作，片段有 Gyroflow 项目时还带一份项目副本。它从不自己改变：播放时你的改动仅用于观看，直到 Save to the moment（保存到精彩瞬间）。关掉 Settings of its own，它就按片段保存的样子播放。片段预览正好相反：它按片段的样子播放，直到你打开这个开关。

标记

M

片段中的时间点，显示在导航栏上。M 在视频当前位置添加一个标记；在标记上按则删除它。在你改动任何一个之前，标记就是相机的精彩时刻：第一次改动会把它们全部保存到这个片段专属的小文件 <clip>.afp.json 中，它还保存你为片段保存的播放方式。删掉这个文件，相机的标记就回来了，片段也会忘掉你保存的播放方式。早期版本的 <clip>.marks.json 会被读取，并在下次改动时变成 .afp.json。

Action Footage Library

Project.afproject

对一个片段做的事在播放器中完成；对许多片段做的事在 Action Footage Library 中完成，这是随播放器附带的 App。它把项目按文件夹浏览（Originals、Footage、Moments、Photos、Exports），带有筛选和搜索，它的命令作用于你选中的内容，作为后台任务逐个运行：

  • 片段预览、标记的精彩瞬间和照片、精彩瞬间的渲染和导出；
  • 为没有运动数据的片段做 Stabilize optically（光学防抖）；
  • Check（检查）和 Find moved files（查找移动过的文件）；Take in another project…（并入另一个项目）；
  • Tags（标签），与每个条目保存在一起；以及 Location（地点）：片段在哪里录制，根据你在差不多同一时间拍的 Apple 照片给出建议（在 Mac 上），或手动设置，还有地点筛选；
  • Info（信息）：片段的日期、相机、地点和播放器使用的镜头配置文件，还没有合适的配置文件时则显示相机的模式编号。

每个片段都有一张缩略图，和访达文件资源管理器画出来的一样快：NAS 上的 300 个片段，第一次 9 秒，之后不到一秒。项目旁边的共享目录保存着它所知道的信息，所以大型项目在每台电脑上都能很快打开。用侧边面板 Project 标签页中的 Open in Action Footage Library（在 Action Footage Library 中打开）打开它，或双击 Project.afproject。

剪掉拍坏的一段

Ctrl+x

项目文件夹

面板 → Project

项目就是你的原始文件所在的地方，即这台电脑上或 NAS 上的任意文件夹（它的位置），再加上它的精彩瞬间、片段预览、导出的文件和照片放在哪里：_Moments/、_Clips/、_Exports/ 和 _Stills/，新生成的放进其中的 Generated/ 文件夹。它的文件 Project.afproject 只保存这些位置；其他一切都在文件本身里，每个文件按片段本身是什么来找到它，所以项目跟着素材走。第一次保存精彩瞬间或导出时，侧边面板的 Project 标签页会问你用哪个文件夹，是片段所在的文件夹还是它上面的某一层，然后 Initialize the project here（在此初始化项目）会创建项目。每个片段的 .afp.json 和 Gyroflow 项目留在它旁边。早期版本的项目会照原样读取。

你的原始文件保持原样，除非你剪掉其中拍坏的一段。

导出与分享

每种风格导出什么，一步步讲清楚 →

所见即所导

Shift+E

按片段正在播放的样子一次导出：防抖与否，同样的变换（视角、强度、地平线、镜头和投影、画幅）和边缘，同样的风格。标记了一段时，只导出这一段；侧边面板的 Output → Export 有 Mark start、Mark end，以及 Export the clip 或 Export the part a–b。对正在导出的片段按两次 Shift+E 可取消导出。

已验证 Osmo Action 6 的 HDR 导出 应可用 Rec.709 导出；其他相机（Gyroflow 支持的任何相机：需要项目）

适合手机的文件

Log 片段导出为 HDR 的 10-bit HEVC（Rec.2100 HLG），并带有相应的标签，让 macOS、iOS 和 YouTube 以 HDR 显示。在 Mac 上以 HLG+DV 风格导出时，还带有供 Apple 设备使用的 Dolby Vision 元数据（见任何屏幕上的 HDR）。NBCU 和相机厂商的 SDR 风格则导出 Rec.709，侧边面板 Output → Export 中的 Export in SDR 也是如此，无论当前播放的是什么：适用于 Log 片段，以及已经是 HDR（HLG 或 PQ）的文件，经 NBCU 的转换。由 mpv 色调映射的 SDR 导出为 HLG，SDR, HLG+DV 导出为带 Dolby Vision 的 HLG。10-bit 素材始终保持 10-bit。

文件存放位置

项目的 _Exports/ 文件夹，文件名是你在与精彩瞬间相同的对话框中起的名字；除非导出的是 HDR, HLG，否则风格会写在括号里：Turtle.mov、Turtle (SDR).mov、Turtle (Dolby Vision).mov。文件带有指向原始文件的链接：没有侧边面板时，右键菜单中的 Open the original 会播放原始片段中的这一段。音频原样复制，文件保留片段的日期。通知会告诉你文件的位置，侧边面板 Output → Export 中的 Show the last export（显示最近一次导出）会在访达文件资源管理器中显示它。

导出时照常观看

导出期间播放继续进行，进度显示在右上角；可以同时导出多个片段。在 Mac 上，视频播放时导出以后台优先级运行，几乎停止：暂停后，导出就全速进行。

一次导出多个片段

Stabilize + LUT（位于访达的快速操作文件资源管理器的右键菜单中）会导出所选视频，Log 导出为 HDR（HLG），放进项目的 _Exports/ 文件夹；没有项目时，放进片段旁边的 stabilized/ 文件夹。命令行也可以，还能写出供剪辑用的 ProRes 422 HQ。Action Footage Library 会导出一次旅行中所有尚未导出的精彩瞬间，每个都按它自己的设置。

时域降噪，边播边做

Ctrl+p · 面板 → Transform

每一帧都用它本身及其前后各 5 帧重建，每一帧都按它们之间的运动对齐到这一帧上：光线昏暗时传感器产生的噪点消失（时域降噪），细节保留。播放时和暂停时都会这样做；画面会晚几帧显示，声音会等它。必须开启防抖。它默认开启，与片段的设置保存在一起；Stronger, for a very noisy clip（更强，用于噪点很多的片段）会纳入更多帧，并去掉暗斑。Performance & Quality → Temporal denoise：在这台电脑上用 Full（完整）、Light（轻度，前后各 3 帧）或 Off（关闭）。不会往文件里写入任何东西：导出的文件按录制原样播放。

Ctrl+f

降噪与水下色彩

降噪

Ctrl+p

经过防抖的片段播放时没有昏暗光线下的噪点：这就是时域降噪，播放时和暂停时都有，你保存的照片也一样。对于没有防抖的片段，dlogm.conf 中的 denoise=yes 会在播放时开启一种较轻的降噪。

水下色边

Ctrl+a · 面板 → Transform → Water

水对蓝光的折射比对红光强，所以在相机平面玻璃后面，红色和蓝色越靠近画面边缘就分得越开。凡是镜头在水下的地方，每种颜色都会被移回它自己的光线落点，完全依据物理计算，不针对素材拟合；在水上则不做任何改变。Transform → Water → Reduce color aberration（减少色差，默认开启，Ctrl+a）保留录制时的色边，再按一次则重新去除；它是片段变换的一部分。在较慢的电脑上，Performance & Quality → Skip color aberration correction（跳过色差校正）只在这块屏幕上不做它。仅用于播放。

在 Osmo Action 6 的潜水片段上，画面边缘红色 3-7 px 的色边缩小到约一个像素以内。

侧边面板

Tab

各项设置都在窗口右侧、视频旁边的面板中，视频会为它让出位置；快捷键标在对应功能旁边。Tab 隐藏或显示面板。

  • Project，面板打开时所在的部分：这次旅行的项目文件夹（Initialize the project here）、Open in Action Footage Library、这个片段的标记和精彩瞬间、标记一段并把它保存为精彩瞬间；

平台与安装

Apple Silicon Mac

日常使用中

macOS 15 或更高版本。App 自带 mpv 和 ffmpeg：无需另装任何东西。它采用 ad hoc 签名，所以第一次打开时：系统设置 → 隐私与安全性 → 仍要打开。它的设置会把它设为 MP4 视频的播放器，添加快速操作，并下载 DJI 的 LUT。下载内容中有两个并列的 App：播放器 ActionFootagePlayer.app，以及 Action Footage Library，即 ActionFootageLibrary.app。

Windows 10 或 11

Alpha

独立的 App，有 x86-64 版和 Windows 11 on ARM 版，所需的一切都已包含在内，Action Footage Library 也在其中：播放器文件夹中的 ActionFootageLibrary.exe，有自己的开始菜单项，Project.afproject 文件会用它打开。x86-64 版已试用且可正常工作，但测试还不多；ARM 版只经过构建检查。它只为你自己安装，无需管理员权限；第一次运行时 SmartScreen 会发出警告：更多信息 → 仍要运行。

Linux

未试用

插件，装进你自己的 mpv：每个发布版本都会构建，但尚未试用。防抖需要带 VapourSynth 构建的 mpv。Action Footage Library 暂时没有 Linux 版，所以没有针对整个旅程的批量任务；其余的事播放器一个片段一个片段地完成。

在你自己的 mpv 中使用插件

适用于任何系统：Log 色彩、遥测数据、精彩时刻和菜单都是纯 Lua 加 GPU 着色器。防抖和导出需要带 VapourSynth 构建的 mpv，并提供适用于 Apple Silicon 上的 macOS、Linux x86-64 和 Windows 的构建。mpv.conf 和 input.conf 中无需添加任何内容。

高级用户选项

设置文件

dlogm.conf
hdr_screen=hdr 和 sdr_screen=dv：Log 片段在 HDR 屏幕和没有 HDR 的屏幕上的起始风格（hdr、dv、dvsdr、tonemap、nbcu 或 maker）；denoise=yes：开启播放时的降噪（它已经没有快捷键或菜单）；dv_live_l1=no（Mac App）：使用 trim 参数的固定亮度信息，而不是每一帧的
gyroflow.conf

fields、units、position、font_size、visible
